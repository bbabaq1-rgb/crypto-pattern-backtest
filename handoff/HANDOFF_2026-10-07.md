## 0. 한 문단 요약

OKX USDT 무기한 선물에서 **차트 패턴을 자동 탐지 → 결정론적 규칙으로 진입 → 거래소 손절 주문을 건 채 방식D로 청산**하는 시스템이다.
실행은 GitHub Actions 러너(서버 없음)이고, 발화는 Supabase pg_cron 이 `workflow_dispatch` 로 깨운다. 상태는 Supabase DB 에 저장한다.
새 규칙은 **사전 등록 → 게이트 v2 → 실거래 프레임 확인 시험**을 전부 통과해야 실거래에 들어간다. 지금까지 시험한 진입·청산·필터
아이디어의 대부분은 기각됐고, **채택된 것은 소수의 패턴 + 위험 관리 규칙(변동성 타겟팅 사이징, 레짐 라우팅)** 이다.
2026-09-06 ~ 10-06 은 "배포 집합을 끄지 않고 1개월 실거래로 관찰"하는 기간이었고 **관찰 보고는 아직 작성 전**이다.

## 1. 불변 원칙 (넘겨받는 쪽도 지켜야 할 것)

1. **거래소 손절 주문이 없으면 실거래하지 않는다.** 진입 직후 OKX algo(손절, reduceOnly)를 건다. 등록 실패 시 진입을 되돌린다.
2. **매매 결정은 결정론적 코드만 한다.** LLM 은 코드 작성·수정·분석만 한다. LLM 판단(엘리엇 카운트·확률표 등)을 매매 방향에 쓰지 않는다.
3. **사전 등록**: 판정 기준·셀·홀드아웃·문턱을 결과 보기 전에 `registry.json` 에 적고 실행한다. 결과를 본 뒤 셀·문턱을 고르지 않는다(사후 선택 금지).
4. **검증 프레임과 실거래 규칙이 다르면 실거래를 검증에 맞춘다.**
5. **단일 해(특히 진행 중인 해)에만 이익인 셀은 게이트를 넘어도 켜지 않는다.**
6. 사용자 결정 사항: 위험 수준(RISK_FRAC / LEV_CAP / MAX_POS), 열린 포지션 수동 청산, 자금 이동, 게이트 문턱 변경.
   사전 등록 기준을 **전부** 통과한 패턴은 자율 반영 가능(2026-09-05 사용자 권한 부여) — 경계값·부분 통과는 제외.
7. `tests.yml`(테스트 73개 파일) 그린이 아니면 머지하지 않는다.

## 2. 시스템 구조

```
[Supabase pg_cron] ──workflow_dispatch──▶ [GitHub Actions 러너]
   daily: UTC 00/04/08/12/16/20 정각            daily_scheduler.yml  → scheduler.py --slow
   fast : 매시 :03                               fast_scheduler.yml   → scheduler.py --fast
                                                 (같은 concurrency 그룹으로 직렬화, GitHub schedule 폴백 없음)
        │
        ├─ fetch_data: OKX 캔들 수집 (1d 900일 / 4h 130일 / 1h 40일)
        ├─ regime_switch: 레짐 라벨 (닫힌 봉만)
        ├─ 디텍터들 → 신호
        ├─ direction_switch: 레짐→방향 라우팅
        ├─ paper_executor: 사이징·진입·청산·장부 (페이퍼 + 실거래)
        │     └─ exchange.py: OKX 주문 (진입, 손절 algo, OCO 브래킷, 청산)
        └─ Supabase: positions / trades / signals / daily_summary / perp_daily / funding_daily
```

주요 파일: `scheduler.py`(메인) · `paper_executor.py`(체결 엔진) · `exchange.py`(OKX) · `sizing.py`(사이징 원본) ·
`regime_switch.py` · `direction_switch.py` · `exit_barriers.py` · `universe.json` · `registry.json` · `gate.py`(게이트 판정 단일 구현).

러너는 매번 파일시스템이 비어 있으므로 **DB 가 유일한 상태 원천**이다. `supabase_schema_patch_2026_09.sql` 이 아직 실행되지 않아
일부 컬럼(entry_ts, qty, leverage, sl_order_id 등)이 복원 시 유실되고, 코드는 폴백으로 동작한다(아래 7절).

## 3. 실행 플로우 (한 번의 틱)

1. **데이터 수집** — 유니버스 80종목(OKX 무기한 30일 거래대금 상위 80, 2026-09-04).
2. **레짐 라벨** — BTC 200일선 20일 기울기 + ETH/BTC 20일선 기울기 + BTC.D(5종 시총 프록시) 기울기, 3중 2 히스테리시스.
   라벨: `bull_btc` / `bull_altseason` / `bear` / `sideways`(거의 안 나옴). **닫힌 봉만** 쓰고 오늘 라벨 = 마지막 닫힌 봉 라벨.
   레짐은 **예측기가 아니라 상태 분류기**로 쓴다(20일 방향 적중 49% — 예측력 ≈0, 그러나 청산 트리거로서 정보는 실재).
3. **탐지**
   - 느린 틱(daily, 4시간마다): 1d 패턴 + 4h 패턴.
   - 빠른 틱(fast, 매시): exit_spec 을 가진 1h 패턴(cascade, tp1)과 청산·손절 점검.
   - 1d 기존 패턴은 **형성 중인 봉(rows[-1])** 에서, 4h 신규 3종·1h 패턴은 **닫힌 봉(rows[-2])** 에서 탐지한다(7절 참조).
4. **라우팅** — engulfing/fvg 는 레짐→방향 표를 따른다. 나머지는 패턴별 레짐 허용 목록.
5. **진입 필터** — 슬롯(MAX_LIVE_POS 13), 같은 종목·방향 실포지션 중복 차단(거래소 실측 + 장부), 같은 봉 중복 키(봉 ts),
   킬스위치(equity < $100 이면 신규 진입 중지, 잔고 조회 실패 시에도 중지), 앙상블 점수 내림차순으로 진입.
6. **사이징** (`sizing.risk_based_size`)
   - 건당 위험 = equity × **RISK_FRAC 1.5%** × 레짐 오버레이(avg_cap>0 이면 롱 ×0.6) × **vol_scale**
   - vol_scale = clip(0.80 / σ20연율, 0.5, 2.0) / 1.1094 → **0.45 ~ 1.80배**
   - 명목가 = 위험 / 손절폭(8%) ≈ equity × 18.75% × vol_scale, 레버리지 = min(**LEV_CAP 3**, 청산거리 ≥ 손절×2 조건)
   - 상한: 포지션당 명목가 ≤ equity 60%, 전체 명목가 ≤ equity 250%, 최소 증거금 $10 미달이면 스킵
7. **주문** — 시장가 진입 → 체결가 재조회 → 손절 algo 등록(exit_spec 패턴은 손절+익절 OCO). 실패 시 진입 되돌림.
   exit_spec 패턴은 체결가 기준으로 배리어를 재계산해 OCO 를 다시 건다(단, 메인 포지션과 종목이 겹치면 생략).
8. **청산**
   - **방식D**(배포 패턴 대부분): 저가가 진입가 −8% 닿으면 손절가 청산 / 반대 신호(engulfing·fvg 만) 종가 청산 /
     레짐 라벨이 진입 때와 달라지면 종가 청산 / **30봉** 경과 시 청산(TF 무관 — 4h 는 5일). 수수료 왕복 0.2%.
   - **eval_I**(exit_spec 패턴): 진입 시 고정한 배리어(OKX OCO 가 집행) + 시간 청산.
   - 매 실행 `ensure_stop_orders` 가 손절 누락을 재등록하고 고아 algo 를 취소한다. `reconcile` 이 거래소 청산 이력을 장부에 반영.
9. **장부** — 실거래는 방식D, 페이퍼로 방식A(±10%/20봉) 병행, 방식R(롱 한정 방향 인지 레짐 청산) 그림자 장부 기록.

## 5. 시험 체계 (어떻게 판정하는가)

- **게이트 v2** (`gate.py`): n ≥ 20, 평균 > 0, **승률 ≥ 35%**, 같은 레짐·코호트 무작위 진입 베이스라인 대비 boot_p < 0.05(k=n), OOS 양구간.
  (v1 은 중앙값>0 이었는데 −8% 손절 아래에서 중앙값이 손절값에 붙어 사실상 승률 50% 를 요구했다 → 2026-09-05 변경)
- **확인 프레임** (실거래 조건으로 다시 잼): 방식D 청산 · 실거래 코호트(PIT 거래대금 순위) · 레짐 조건부 진입 · 실거래 사이징 자산곡선.
  - C1 게이트 v2 · C2 홀드아웃 · **C2b** train 자체 게이트 통과 & train n ≥ holdout n/2 · C3 자산곡선 CAGR>0, Calmar>0
  - **홀드아웃은 국면 기준(frame_v3)**: 셀 레짐으로 라벨된 최근 365일 + 에피소드 OOS. 달력 홀드아웃은 하락장 1년이 판정을 지배해서 바꿨다.
  - 레짐 셀 n<200 이고 train 탈락 사유가 boot_p 뿐이면 INCONCLUSIVE(기각 아님).
  - 다중 셀이면 Holm 보정, 왕복 마찰 0.4% 스트레스 병기.
- **짝지음 시험**(청산·사이징 규칙): 같은 신호에 두 규칙을 동시에 적용해 비교. 자산곡선은 실거래 사이징으로.
- **포트폴리오 프레임**(`validate_portfolio`): 슬롯·증거금 경합이 걸린 규칙은 패턴 단독이 아니라 배포 집합 전체 자산곡선으로 판정.
- **음성 대조**: 경제적 내용이 없는 계열(AR(1), 사인파, 상수)을 같이 돌려 '자기상관만으로 나오는 IC'를 잰다. 대조가 통과하면 판 전체 INVALID.
- 결과는 `registry.json` 에 사전 등록 키로, 실행 기록은 `research_log.csv`, 보고서는 `report_*.md`.
